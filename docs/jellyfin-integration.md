# Jellyfin Integration Surfaces

Operating "inside Jellyfin" means that every plugin capability is embedded directly within Jellyfin's native administrative, user, background, and metadata structures, rather than requiring external infrastructure, cluster orchestrators, identity provider federation, or out-of-band management dashboards. In Jellyfin 12, server-wide settings belong on the plugin configuration page ([`Plugin.GetPages`](../src/JellySin.Plugin.Lastfm/Plugin.cs)) within the administrator Dashboard, background operations execute as native scheduled tasks ([`IScheduledTask`](../src/JellySin.Plugin.Lastfm/Tasks/AccountTask.cs)) or post-scan library handlers ([`ILibraryPostScanTask`](../src/JellySin.Plugin.Lastfm/Tasks/LibraryScanRematchTask.cs)), and remote metadata enrichment plugs into standard library provider pipelines ([`IRemoteMetadataProvider`](../src/JellySin.Plugin.Lastfm/Metadata/LastfmArtistProvider.cs), [`IExternalUrlProvider`](../src/JellySin.Plugin.Lastfm/Metadata/LastfmExternalUrlProvider.cs)).

For listeners, "inside Jellyfin" requires that all user-facing functions—connecting Last.fm accounts, setting scrobbling preferences, configuring exclusions, reviewing scrobble logs and delivery status, synchronizing favourites, importing history, exploring music recommendations, and managing dynamic playlists—reside within the web client's native user preferences interface (`#/mypreferencesmenu`) using the listener's active authentication session. Today, these listener features live in a standalone single-page application under `/JellySin/Lastfm/`, which requires separate Jellyfin credential entry or Quick Connect polling, and relies on manual `menuLinks` configuration in `config.json`. The architectural migration to eliminate the standalone application and embed user surfaces directly into Jellyfin's user preferences is defined and tracked in [#197](https://github.com/jellysin/plugin-lastfm/issues/197).

## Gaps

Each gap maps to an item of the plan in [#197](https://github.com/jellysin/plugin-lastfm/issues/197).

- **Entry script in the served web client** (#197, item 2): the plugin adds its own script to the web client's `index.html`; the script adds a "Last.fm" row to user settings (`#/mypreferencesmenu`).
- **In-client Last.fm page** (#197, item 3): every user row of the table above moves to a page inside the web client that uses the client's own session. The Last.fm return address points to that page, and so does the administration page link (`admin.html:9`).
- **Separate page and its sign-in removed** (#197, item 4): `/JellySin/Lastfm/` ([`PublicController.cs:21`](../src/JellySin.Plugin.Lastfm/Api/PublicController.cs)), the password form ([`web/auth.ts:16`](../web/auth.ts)) and the Quick Connect status endpoint ([`PublicController.cs:45`](../src/JellySin.Plugin.Lastfm/Api/PublicController.cs), [`QuickConnectLimiter.cs:29`](../src/JellySin.Plugin.Lastfm/Api/QuickConnectLimiter.cs)) go away, with a migration note. The `menuLinks` instructions in [operations.md](operations.md) go with them.
- **Per-release integration test** (#197, item 5): Jellyfin 12.2 and 12.3, with a screenshot of each surface. A changed settings page structure turns the test red.

Known limits: a server that does not host the web client gets no entry, and native apps that do not use the server's web client do not show it. Scrobbling and the administrator settings work in both cases.

## Not Assumed

- **No cluster**: The plugin does not assume a cluster architecture; state documents, submission retry queues, and cryptographic key rings are persisted directly to single-node local filesystem paths under `jellysin-lastfm/` in Jellyfin's data directory with local in-process concurrency gating ([`docs/operations.md:172`](operations.md)).
- **No identity provider**: The plugin does not assume an external identity provider; user authentication and caller identity are derived exclusively from Jellyfin's native session authorization context, binding Last.fm sessions to local Jellyfin `UserId` GUIDs without external IdP federation ([`src/JellySin.Plugin.Lastfm/Api/CallerFilter.cs:15`](../src/JellySin.Plugin.Lastfm/Api/CallerFilter.cs)).
- **No reverse proxy**: The plugin does not assume or require a reverse proxy; the URL resolution logic falls back directly to request scheme and host attributes when no published server URL is configured ([`src/JellySin.Plugin.Lastfm/Api/ServerAddress.cs:18`](../src/JellySin.Plugin.Lastfm/Api/ServerAddress.cs)).
